# Delta for Additive Harness Engine

## ADDED Requirements

### Requirement: v3.1.1 final release assets

The release process MUST publish an immutable `v3.1.1` release from the accepted RC26 commit and preserve the current authored installation documentation in its final archive. The release MUST expose the final archive, its SHA-256 checksum, and `release-manifest.json` as validated assets. Release execution, tag mutation, and publication remain outside the installer and acceptance behavior.

#### Scenario: Final asset set is complete

- GIVEN the accepted RC26 commit and authored documentation are selected for promotion
- WHEN the v3.1.1 release assets are prepared
- THEN `pegasus-harness-v3.1.1.tar.gz`, its `.sha256` file, and `release-manifest.json` are present
- AND the manifest records the release tag, archive identity, checksums, and included documentation

#### Scenario: Invalid final identity is refused

- GIVEN an archive, checksum, or manifest is missing, mismatched, or associated with another commit/tag
- WHEN final-release validation runs
- THEN validation MUST fail before the release is considered distributable

### Requirement: Versioned and latest asset identity

Each required asset MUST be reachable through both its immutable versioned URL under `releases/download/v3.1.1/` and the corresponding `releases/latest/download/` URL. The latest locator MUST resolve to the v3.1.1 asset with the same basename and SHA-256 identity; it MUST NOT silently resolve to an RC, a different release, or a regenerated byte variant.

#### Scenario: Versioned and latest URLs agree

- GIVEN the published v3.1.1 archive, checksum, and manifest
- WHEN consumers download each asset through both locator forms
- THEN every pair has the same basename and bytes
- AND checksum and manifest validation identify v3.1.1 consistently

#### Scenario: Latest points elsewhere

- GIVEN a latest-download response has a different asset name, digest, tag identity, or incomplete asset set
- WHEN distribution verification compares it with the versioned v3.1.1 assets
- THEN verification MUST fail and the release MUST NOT be reported as ready
